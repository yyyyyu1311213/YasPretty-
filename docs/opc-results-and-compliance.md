# YasPretty 小Y 成果状态与第三方资源合规说明

截至 2026 年 11 月 6 日（北京时间），YasPretty 小Y处于“已上线的早期实际应用 MVP”阶段。作品已形成可启动、可操作、可测试的 React + Vite 主站和 Node.js + Fastify 服务端，并已通过 Netlify 公网入口提供试用：<https://yaspretty.netlify.app/>。团队已经开展用户测试、试用和评价收集，但当前材料未补录样本量、周期和统计口径，因此不把定性试用反馈写成大规模用户数据，也不能表述为完整产品或成熟商业化应用。

本文对应《超级个体（OPC）·数字新消费》专项赛《OPC 创新实践说明》中“成果状态、验证及应用价值”和“第三方资源及合规说明”两部分。所有“已完成”均以当前代码、数据文件、测试记录和可运行入口为依据；图片授权、智谱联网检索额度/权限和真实用户试用等未完成事项保留为风险，不以规划替代事实。

## 一、成果状态、验证及应用价值

### 1. 当前阶段判断

作品当前属于 **MVP（已上线早期实际应用版）**，同时包含一部分仍在完善的体验、数据治理和品类扩展工作。

不属于以下状态：

- 不是只有概念、策划书或静态效果图的 Prototype；核心产品浏览、推荐和妆容方案流程已经可以运行。
- 不是成熟商业化产品；当前没有账号体系、跨设备同步、支付、库存或物流，也没有可对外引用的营收和留存数据。
- 已进入实际应用和试用阶段，但现阶段用户测试、试用和评价尚未形成可公开引用的统计报告；不能把评价收集写成大规模真实用户评分。

### 2. 已完成并可现场演示的成果

**产品资料库。** 当前受控产品数据共 35 条，覆盖粉底液、气垫、遮瑕、散粉、眼影、睫毛膏、腮红和唇妆 8 个品类。用户可以搜索、按肤质/妆效/遮瑕力/价格筛选和排序，打开产品详情与完整核验档案，并在浏览器本地保存“想买、正在用、会回购”等匿名状态。

当前产品库以底妆资料为主，其他彩妆品类数量相对有限；后续将继续增加经过核验的眼妆、腮红、眉妆和唇妆产品，不用批量模板或模型生成未经核验的商品事实填充数量。

**小Y与统一意图路由。** 小Y保留站内本地规则推荐，并由服务端 `intentRouter` 区分产品库推荐、产品事实、妆容方案、产品库外问题和需要时效检索的问题。前端只调用 YasPretty API，第三方密钥不进入浏览器。没有服务端智谱 Key 时，产品浏览和本地推荐继续可用；外部智能服务不可用时会显示明确的降级或错误状态，不以旧知识伪装联网结果。

**结构化妆容工作台。** 用户可以填写肤质、色调倾向、妆效、场景、风格、预算、预计带妆时长、熟练度和优先目标，生成包含妆前、底妆、局部遮瑕、定妆、眉眼、腮红和唇妆的 7 步方案。方案展示候选筛选依据、取舍、注意事项、置信度、来源模式和局限，并可从结果打开站内产品详情。模型输出先经过 schema、产品 ID 和硬条件校验；模型未配置、超时、解析失败或返回无效产品时使用本地规则方案降级。

**交互与展示。** 首页提供品牌开幕、可跳过/减少动效、互动化妆桌、产品精选轮播、搜索入口和“创建我的妆容方案”主操作。桌面端使用 Three.js/React Three Fiber 的按需 3D 化妆桌，资源受限或 WebGL 不可用时回退到 2D 品类桌；产品详情和导航历史支持桌面、手机浏览器的站内回退路径。

**隐私与安全边界。** 当前不接收照片，不进行 MediaPipe 人脸分析，也不保存照片。小Y画像、对话和收藏仅保存在当前浏览器的版本化 `localStorage`；匿名本地保存不等同于服务端永久保存。服务端已实现请求 schema、64 KiB 请求体限制、超时、有限重试、每 IP 限流、单进程每日额度、安全响应头和脱敏日志。

**上线与试用。** 当前公网入口为 <https://yaspretty.netlify.app/>；2026 年 11 月 5 日检查返回 HTTP 200。该入口用于早期用户试用和评价收集，公网可访问不等同于已完成多实例生产部署、持续监控、账号体系或商业化运营。

### 4. 使用场景与应用价值

作品面向美妆新手、具有预算/肤质/妆效约束的消费者，以及需要完整妆容步骤的普通用户。典型场景包括通勤、约会、拍摄/答辩和长时间带妆。

- 对用户：把分散的肤质、场景、预算、妆效和产品信息组织成可修改的决策条件，减少从大量商品中逐一筛选的成本。
- 对决策可信度：推荐先执行品类、预算、排除品牌等硬条件，再按肤质、场景和妆效形成可解释候选依据，避免让模型直接创造商品、价格或色号。
- 对使用连续性：模型或联网服务失败时仍可完成产品浏览和本地规则方案；用户可以修改预算、场景或妆效后重新生成，不需要重新学习提问方式。
- 对长期产品化：产品 ID、来源、核验状态、图片授权状态和方案 schema 已分开记录，为后续扩展产品品类、照片辅助和多用户能力留下可审计边界。

### 2. AI 工具使用说明建议填法

报名系统和统一模板应选择“已使用”，但要把“开发辅助”和“运行时 AI 服务”分开说明，不用“AI 占比”之类无法核实的百分比。

**代表性过程一：开发辅助与视觉资产。** OpenAI Codex 用于协助代码编写、组件适配、测试整理、文档整理和部分品牌视觉资产的代码化导出。学生先确定产品定位、页面结构、数据字段、推荐边界和视觉方向，再对生成或辅助生成的代码、SVG、栅格文件和文案进行筛选、修改、联调、测试和版本管理。最终保留的品牌资产由项目代码生成，来源和生成方式记录在 `public/assets/asset-manifest.json`；Codex 不替代学生的产品决策、架构设计、产品数据核验和最终验收。

**代表性过程二：运行时结构化推荐。** 智谱 GLM 在服务端用于组织小Y回答和可选的结构化妆容方案。主要输入是用户主动填写的结构化妆容条件和受控候选产品；模型不能直接访问或修改产品事实。服务端先执行预算、品类、排除项等硬条件，再将候选及 evidence 交给模型；返回结果经过 JSON 提取、schema、产品 ID 和硬条件校验，最多进行一次结构修复，失败后改用本地 7 步规则模板。无 Key 时展示本地规则降级；2026-11-06 已用不含个人数据的短请求完成一次真实 GLM 对话链路验收，但尚未据此评估模型效果、稳定性或并发能力。

**代表性过程三：时效问题检索。** 智谱 `web-search-pro` 仅在 `intentRouter` 判断需要时效事实时由服务端调用；来源标题、链接、发布方和访问时间随回答返回。网页内容被视为不可信资料，不能覆盖系统提示或要求泄露密钥；检索失败时向用户说明失败，不用模型旧知识伪装刚刚联网获得的事实。

### 3. 学生原创贡献与 AI 边界
